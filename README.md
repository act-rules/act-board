# act-board

Inventory of every ACT rule: one generated GitHub issue per rule, shown in a
table Project. A weekly Action (and manual dispatch) recomputes status from
`act-rules.github.io` and `w3c/wcag-act-rules` using
[act-tools](https://github.com/act-rules/act-tools).

## How to use issues

Issue titles and bodies are generated by the bot. **Do not edit the body.**
Leave comments instead.

Community Group issues on `act-rules/act-rules.github.io` with the `Blocker`
label become cross-repo sub-issues of the matching act-board rule (or the
lowest rule id, when one blocker matches several rules). Removing that label
or closing the CG issue is how a blocker falls off the board.

## Secrets and variables

Create these on the repository before the first workflow run. The job fails
immediately if they are missing.

**Actions secrets**

- `APP_ID` — GitHub App id for `act-board-sync` (or the org app installed on
  this repo and `act-rules.github.io`)
- `APP_PRIVATE_KEY` — App private key (PEM). Never commit this value.

**Actions variables**

- `ACT_BOARD_PROJECT_NUMBER` — Projects v2 number for the ACT board table

The App needs Contents and Issues read/write on `act-board` and
`act-rules.github.io`, Metadata read, and organization Projects read/write.

## Workflow

[`.github/workflows/sync.yml`](.github/workflows/sync.yml) runs Mondays at
06:00 UTC and on `workflow_dispatch`. It:

1. Classifies every rule (`yarn approval-report`)
2. Upserts act-board issues and blocker sub-issues
3. Syncs Project **Status** and optional fields (type, counts, dates, review
   PR URL) when they differ from the classifier
4. Commits [`data/snapshot.json`](data/snapshot.json) only when that JSON
   actually changed

Optional Project fields that do not exist yet are skipped with a warning.
A missing Status field fails the job.

Manual run: **Actions → Sync ACT board → Run workflow**.
